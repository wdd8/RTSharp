Requirements:

RT# is built on .NET 10. There are two flavors of each release: the regular version which requires the .NET 10 runtime to be installed on your computer, and the self-contained version which includes everything it needs to run and therefore does not require any installation of .NET.

The Linux packages always use the regular version and declare the .NET runtime as a dependency, so your package manager installs it for you.

RT# works on the following operating systems:

Application: Windows, Linux and macOS
RTSharp.Daemon: Linux only

Application:

Windows and macOS: just extract the release archive into a folder of your choosing and start RTSharp (RTSharp.exe on Windows). There is no setup program.

Linux: install the client package with your package manager. The package installs the application to /usr/lib/rtsharp and creates the rtsharp command. Start RT# by running rtsharp in a terminal. No menu entry is created. The package recommends mpv (torrent file preview) and xchm (CHM help viewer); pacman lists them as optional dependencies instead.

The first time you run RT#, you will be asked if you want to generate a new client certificate. A client certificate is required to communicate with the daemon. Unless you have one of your own, answer "Yes".

RT# stores all its configuration files in the following folder:

Windows and macOS: the "user" folder inside the application folder
Linux: $XDG_CONFIG_HOME/rtsharp, which is usually ~/.config/rtsharp

In this folder you will find the config.json file (servers, options and window layout), the client.pem and client.key files (your client certificate), the "plugins" folder with one configuration file for each plugin instance and the local caches.

The plugins themselves are located in the "plugins" folder of the application folder, each plugin in its own sub folder with its manifest.json file.

RTSharp.Daemon:

There are two ways to run RTSharp.Daemon on your server:

- Systemd service: install the rtsharp-daemon package (.deb, .rpm or .pkg.tar.zst). The package installs the ASP.NET Core .NET 10 runtime as a dependency, and the configuration file is /etc/rtsharp-daemon/appsettings.json. The service is not started or enabled by the installation, so you have to complete these steps:
  1. Set the user and group the daemon runs as: systemctl edit rtsharp-daemon, then add User= and Group= under [Service]. The .deb installer asks for the user and fills it in for you, but check it.
  2. Enable and start the service: systemctl enable --now rtsharp-daemon.
- Docker container: see the docker-compose.yml file of the daemon for an example configuration. An example configuration will be created upon the first startup.

Since RTSharp.Daemon performs the file operations on the torrent data (move, duplicate, remove), we strongly recommend you to run it under the same user as your torrent daemons. The configuration of the daemon is explained in the "Server daemon" chapter.

Optional programs:

RT# can preview the files of a torrent with mpv. If you want to use this feature, mpv must be installed on your computer and available in the PATH. The mediainfo feature uses mediainfo on the server side.

Help file:

This help file (RTSharp.chm) is located in the application folder (/usr/lib/rtsharp for the Linux packages), you can open it at any time with the F1 key or with the "Help/Contents" menu. On Windows it is opened with the standard HTML Help viewer. On Linux and macOS there is no CHM viewer installed by default, RT# will open it with the program associated to .chm files, such as xCHM or KchmViewer.
