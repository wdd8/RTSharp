The torrent daemons are configured in the DataProviders section of appsettings.json. There are currently 3 supported daemon types, so there are at most 3 keys in DataProviders: "rtorrent", "qbittorrent" and "transmission". Each type contains one entry for each daemon instance, where the key is the name of the instance. This is the name that you will enter as "Data provider name" when you configure the data provider in RT#.

"DataProviders": {
  "rtorrent": {
    "my rtorrent": {
      "SCGIListen": "127.0.0.1:5000",
      "SessionDir": "/home/user/.session",
      "LogFile": "/home/user/.session/rtorrent.log"
    }
  },
  "qbittorrent": {
    "my qbittorrent": {
      "Uri": "http://127.0.0.1:1234/",
      "ApiKey": "api-key"
    }
  },
  "transmission": {
    "my transmission": {
      "Uri": "http://127.0.0.1:1234/transmission/rpc",
      "Username": "transmission",
      "Password": "changeme"
    }
  }
}

Restart the daemon after any change of this section.

1. rtorrent:

- SCGIListen: The IP end point of the SCGI socket, as configured by the scgi_port option of rtorrent
- SessionDir: Optional, overrides the session directory returned by rtorrent. This is useful when rtorrent runs in a file system that is not visible to the daemon (ie. in a container). It impacts the ability to get the .torrent files of the torrents
- LogFile: Optional, the log file of rtorrent, for streaming the logs to RT#. If you have rtorrent logging enabled, set this to the value of the log.open_file option

2. qBittorrent:

- Uri: The address of the qBittorrent WebUI, for example http://10.0.0.1:40000/
- ApiKey: The API key generated from the qBittorrent WebUI
- Username / Password: The credentials of the WebUI, if you don't use an API key

The API key is superior to the username and password, we recommend you to use it whenever possible.

3. Transmission:

- Uri: The address of the RPC path, for example http://10.0.0.1:40000/transmission/rpc
- Username / Password: The credentials of the RPC server
- ConfigDir: Optional, overrides the config directory returned by Transmission, for the same reason as SessionDir of rtorrent
- LogFile: Optional, the log file of Transmission, for streaming the logs to RT#

* RTSharp.Daemon accesses the torrent data directly, so it should be run under the same user as your torrent daemons.
