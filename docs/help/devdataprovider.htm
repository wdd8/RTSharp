A data provider is a plugin that connects RT# to a torrent daemon. It is written like any other plugin, except that its manifest declares "Type": "DATA_PROVIDER" and that it registers an implementation of IDataProvider during Init:

public override async Task<IPlugin> Init(IPluginHost<MyDataProviderConfig> Host, Action<(string Status, float Percentage)> Progress)
{
    var dp = new DataProvider(this);
    this.Host = Host.RegisterDataProvider<MyDataProviderConfig>(dp);
    Disposables.Add(this.Host);
    return this;
}

The configuration class of a data provider derives from PluginConfigContainer<DataProviderInstanceConfig>, so it carries the server id, the data provider name on the daemon and the color of the instance. RegisterDataProvider returns an IDataProviderHost<TConfig>, which is the plugin host with some more functions for data providers, such as AttachedDaemonService (the server this instance is attached to) and GetBuiltInDataProviderGrpcHeaders (the headers that select this daemon on the server).

1. Capabilities:

IDataProvider exposes its capabilities with DataProviderCapabilities, and its sub parts with their own capabilities: Files (IDataProviderFiles), Tracker (IDataProviderTracker), Peer (IDataProviderPeer) and Stats (IDataProviderStats). RT# uses them to enable or disable the menu items, so be honest: if your daemon cannot stop a torrent, set StopTorrent to false and the Stop button will be disabled for your torrents.

2. The listing:

The most important function is GetTorrentChanges, it returns a channel of ListingChanges which contains the torrents that have been added, changed and removed since the last change. RT# applies these changes to the listing. The more precise your changes are, the less RT# has to work, so try to only send the torrents that have really changed.

3. The details:

GetFiles, GetPeers, GetTrackers and GetPieces return the details of a list of torrents, while GetFileChanges streams the file changes of one torrent while the Files tab is visible.

4. The actions:

StartTorrents, PauseTorrents, StopTorrents, AddTorrents, RemoveTorrents, SetLabels... return a TorrentStatuses, which is the list of the torrents with the errors that happened for each of them, if any. Long actions such as ForceRecheck and MoveDownloadDirectory return the id of a script running on the server, RT# follows its progress in the action queue.

The three built-in data providers (rtorrent, qbittorrent and transmission) are good examples, they all go through RTSharp.Daemon with gRPC.
