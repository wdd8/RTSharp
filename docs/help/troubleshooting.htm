Here are the most common problems and how to solve them. In all cases, the Log tab is the first place to look at, it usually tells you exactly what went wrong.

The server cannot be reached:

Select the server in the Servers window and read its status. If the connection is refused or times out, check that RTSharp.Daemon is running, that the port matches its ListenAddress setting and that no firewall blocks the connection. If the connection is closed during the handshake, the daemon has probably rejected your client: check that the thumbprint of your client.pem is in the AllowedClients list of the daemon and that you have restarted the daemon after adding it.

RT# asks me if I trust the server certificate:

The certificate presented by the server does not match the thumbprint you have entered in the Servers window. If you have just regenerated the certificate of the server, check its new thumbprint and answer "Yes". Otherwise answer "No" and find out why the certificate has changed.

A data provider does not appear:

The changes of plugin configuration are only applied after a restart of RT#. Also check that the "Data provider name" of the instance is exactly the name used in the DataProviders section of the daemon configuration, including casing, and that the daemon has been restarted after its configuration has been modified.

A menu item is disabled:

The torrent daemon of one of the selected torrents does not support this action, see the "Torrent daemons" chapter. For example qBittorrent cannot stop torrents and Transmission cannot pause them. Also some actions only make sense for some states, you cannot start a torrent that is already downloading.

"Get .torrent" fails:

The daemon reads the .torrent files from the session directory of rtorrent or from the config directory of Transmission. If the torrent daemon runs in a container or in a file system that is not visible to RTSharp.Daemon, set SessionDir or ConfigDir in the daemon configuration.

The "Logs" item is missing:

Set the LogFile setting of the data provider in the daemon configuration, and make sure that the torrent daemon really writes its log in this file.

mpv has not been found:

Install mpv on your computer and make sure that it is available in the PATH, then try again.

RT# displays "RTSharp has crashed":

An unexpected error happened. The message contains the details of the error, please copy them and report the problem.
